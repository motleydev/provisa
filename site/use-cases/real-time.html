01Scenario — Live operational board

Warehouse operations wants a live board of scanner events and order status changes, where each regional manager sees only their own warehouses.

Scanners POST JSON events, singly or in batches, to an ingest source; dot-notation paths map nested payloads to steward-declared columns. Order changes in PostgreSQL arrive through auto-installed triggers and LISTEN/NOTIFY; other databases use Debezium CDC. The board subscribes over SSE, with row-level security and masking applied per subscriber. A Kafka sink can forward the same stream to a topic.

Ingest sources accept events over HTTP. A scanner POSTs {"warehouse_id":"WH-03","scan_time":"2026-10-21T14:32:10Z","item":"SKU-4472"} and the ingest source maps warehouse_id, scan_time and item to columns declared by a steward. CDC tracks order changes in PostgreSQL with triggers and LISTEN/NOTIFY, or from other databases with Debezium.

The board subscribes to an SSE endpoint. Each subscriber gets only the events their role may see: a regional manager's subscription applies a row filter on warehouse_id, so they see only their own warehouses' events. Masked columns never appear in the stream. A Kafka sink can forward the governed stream to a topic for other consumers.
