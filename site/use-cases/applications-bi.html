Use Cases · Applications and BI

One model, every surface. The same rules on every protocol.

One governed model serves BI tools, application back ends and chat, with the same row and column rules on every protocol. An application team provides data to a BI team for reporting. An application team builds BFF endpoints for a suite of solutions. A BI portal adds a chat interface. Each is the same model, accessed over a different surface.

The pgwire server lets Tableau, Power BI and DBeaver connect as if to PostgreSQL. GraphQL serves BFF endpoints with automatic persisted queries. A natural-language query endpoint turns each question into SQL, GraphQL and Cypher, runs all three and returns the results. Row-level security and masking apply the same way on every protocol.

01 Scenario one — BI protocols

An application team provides data to a BI team for reporting.

The pgwire server lets Tableau, Power BI and DBeaver connect as if to PostgreSQL; JDBC and Arrow Flight are also served. Row-level security and masking apply the same way on every protocol.

A BI team connects Tableau, Power BI or DBeaver to Provisa's pgwire server using the same connection string they would use for PostgreSQL. The governed model serves data over pgwire, with the same row filters and column visibility rules that apply on every other surface.

JDBC serves Java applications. Arrow Flight delivers bulk results efficiently for large datasets. Every query lands in the append-only audit log, with user, role, tables, status and duration recorded.

02 Scenario two — BFF endpoints

An application team builds BFF endpoints for a suite of solutions, with an admin feature so a group admin can grant data to specific people.

GraphQL with automatic persisted queries, plus a per-role gRPC surface. Row-level security, role inheritance and an approval hook for ABAC rules too complex for static row rules. Org admins approve or deny requests to join the org.

A suite of solutions reads data over GraphQL. The schema is generated from the governed model, and automatic persisted queries let the app send a query hash instead of the full query text on every request. gRPC serves per-role surfaces with protobuf schemas.

Row-level security injects filters before the engine runs the statement. Role inheritance lets a manager role inherit the data access of the team member role. When static row rules are too complex, an approval hook runs for each query, and an org admin approves or denies requests to join the org.

03 Scenario three — Chat interface

A BI portal adds a chat interface.

A natural-language query endpoint turns each question into SQL, GraphQL and Cypher, runs all three and returns the results. The LLM sees only the schema the asking user's role can see. Generated queries run under that user's rights and can be saved for reuse. A per-role rate limit caps LLM spend, and every query lands in the audit log. An MCP server lets an AI assistant act as the chat front end over the same catalog.

A BI portal adds a chat interface by calling Provisa's natural-language query endpoint. A user asks a question in plain language, and Provisa turns it into SQL, GraphQL and Cypher, runs all three, and returns the results. The LLM sees only the schema the user's role may see, so a masked or hidden column never appears in the generated query.

Generated queries run under the user's rights, with the same row filters and column visibility as any other surface. A per-role rate limit caps LLM spend. Every query lands in the append-only audit log. An MCP server lets an AI assistant act as the chat front end, querying the catalog over MCP with the same governed pipeline.
