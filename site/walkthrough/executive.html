Where money and risk leak today

  1. 01Four tools, one data estate. Federation, metrics layer, catalog and policy engine each keep their own description of the same data — and each is licensed, integrated and reconciled separately.
  2. 02Copies to make data usable. Pipelines copy data into a warehouse before anyone can join it. Every copy is compute, storage and another store to secure.
  3. 03Security rebuilt per channel. BI tools, APIs and services each re-implement access rules. Drift between them is audit risk.
  4. 04AI is arriving faster than controls. Teams want agents on company data now. Direct database access gives an agent no policy and little audit trail.

None of these is a technology failure. They are the cost of describing the same data in many places.

What it consolidates — and what it keeps

Consolidates into one model

  • Data federation / virtualization layer
  • Semantic and metrics layer
  • Per-tool access rules and row filters
  • Hand-built APIs and backend glue services
  • Pipelines whose only job is to make a join possible

Keeps — and makes more valuable

  • Warehouse & lakehouse Becomes a replaceable execution engine
  • Data catalog Fed automatically — OpenMetadata, Collibra, Atlan, DataHub
  • Identity provider Okta, Azure AD, Ping, SAML, LDAP
  • Policy engine Plugged in as the final approval step
  • BI tools Connect as if to Postgres or over JDBC

Consolidation without rip-and-replace: the systems you keep get a single governed front door.

Decide whose meter is running

  1. 01Route each query to the cheapest path. Single-source queries go straight to the source and skip federation. Cross-source queries fan out only when they must.
  2. 02Reuse work already paid for. Queries rewrite onto a fresh materialized view automatically. Views refresh only when their inputs change.
  3. 03Stop paying for copies. Join across sources in place, without a pipeline into a warehouse first. Fewer copies to store, secure and delete.
  4. 04Place workloads deliberately. Keep steady workloads on hardware you own and send bursts to the cloud — and keep agent traffic off your systems of record.

Made centrally, as policy: routing, freshness and refresh rules are declared once and apply to every consumer.

Vendors compete for your workloads

Today
Semantics and policy live inside one engine or warehouse. Switching means rebuilding them.
With Provisa
Model, semantics and policy sit above the engine. Queries and policies don't change when the engine does.
At renewal
Embedded engine, Trino, Snowflake, Databricks — move workloads to the best price and performance.
Re-point sources invisibly
Move a table from Oracle to Postgres, or MongoDB to Snowflake; consumers never see it move.
Leave with everything
The model is declarative config in git, and the SQL it compiles is yours to read and keep.
No lock-in on Provisa either
Each release converts to an open-source license (GPL v2+) four years after it ships.

Modernize table by table, not big-bang

A stable, governed API in front of the migration. Consumers keep querying the same model while sources move behind it, one table at a time. Legacy and modern sources share one governance model throughout.

Start from what you have
Import tables, keys, relationships and metrics from dbt, Cube, Snowflake, Databricks and other semantic layers. Every import is reviewed before it registers.
Bring existing APIs over
Hasura v2 metadata converts automatically — permissions, relationships, actions and triggers. Anything that can't map is reported, not dropped.
Ship through your process
Changes are made in an isolated copy and exported as patches for your own release approval — manual or fully automated.

What usually derails migrations — mixed governance models and reconciliation spreadsheets — is designed out.

Say yes to AI agents — safely

  1. 01Same rules as people. Agents connect over MCP; their login maps to a role, so every query passes the same governance.
  2. 02Same audit trail. Each agent query is recorded alongside human queries — who, which role, what was applied.
  3. 03Sources protected. Agent workloads can run on a separate engine, with load windows that protect busy sources.
  4. 04Shared meaning. Glossary, metrics and approved relationships keep agents working from your definitions, not guesses.

A data catalog tells an agent what it should do. Provisa enforces what it can do.

Risk and compliance, in one place

  1. 01No way around it. Access rules are compiled into every query, for every tool, app and agent.
  2. 02Your audit, your data. The audit trail lives in your organization's own store — not the vendor's.
  3. 03Residency enforced. Data can be pinned to a region; reads elsewhere are filtered at home or refused.
  4. 04Keys you hold. Create your own organization key to encrypt secrets and files at rest.
  5. 05Inside your boundary. Self-host on your own infrastructure — airgapped if needed — or use a dedicated hosted platform.
  6. 06Access that stays current. Grants can expire, unused access is removed, and every rule records why it exists.

Hosted service: there is no third-party assurance report yet. Organizations that need one today can self-host. Full detail is in the CISO briefing.

Authorship is federated; enforcement is shared

01 · Domains own their data
Each business domain registers its own sources, tables and relationships. Its rights stop at its boundary.
02 · Data products, not tickets
Domains publish data products with a named owner, purpose, terms of use and quality measures — open standard (ODPS).
03 · Central policy still applies
Identity, policy and catalog stay shared, and every query is governed the same way.

The decision: a scoped pilot

01 · Pick one use case
BI without a warehouse copy, an API over mismatched sources, or AI agents on governed data.
02 · Connect real sources
Two or three systems the use case depends on, with one restricted role.
03 · Measure
Agree the metrics below before starting, with a baseline from today.
04 · Decide
Expand, adjust or stop — on evidence, not slides.

Suggested success measures

CFO
Compute and egress per workload; pipelines and copies avoided
CIO
Time from request to governed access; policies verified by security
Both
AI and analyst use cases served under one policy; security review passed
