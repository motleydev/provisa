Provisa / Install
Install

One wheel. Everything inside.

# Python 3.12 — 3.13 is not supported.
# Not Linux aarch64: no pgserver wheel and no source distribution,
# so the embedded tier does not run there. Use the container tier.
python3 -m venv .venv && source .venv/bin/activate
pip install "provisa[embedded]"

provisa run          # your data
provisa run --demo   # the bundled sample domains, on embedded SQLite

Current release 0.1.0a479. This is a first release and we say so.

The embedded tier runs on DuckDB. No JVM means no Trino — this is the whole control plane and UI on one engine, not multi-engine federation in a wheel. For that, point it at an engine you run.

Download for macOS Download for Windows Download for Linux

The desktop installer is a single download driven by start, stop, status and open. By default it runs everything natively: DuckDB as the federation engine, an embedded PostgreSQL control plane, an in-memory cache. Trino on Docker or an external engine are opt-in choices in the setup wizard, and Docker or a VM is provisioned only if you pick one of them. The run command waits for the API to report ready before it prints success, so a green line means a green line.

01 What is running

Three processes and no cluster.

The engine

DuckDB, in process. It is the only engine in the wheel — omitting the JVM omits Trino. Good for a desktop, an edge box and development; not for multi-user production, and we would rather tell you that here than have you find out in staging.

The control plane

An embedded store holding the model, the operating state and the platform state — pluggable, chosen by a SQLAlchemy URI, and PostgreSQL everywhere that is not a desktop. One consequence worth knowing before you build a control narrative on it: audit-log immutability is enforced by PostgreSQL rules, so on the desktop tier append-only is an application convention rather than a database guarantee.

The cache

In memory on the desktop. Redis where one is configured.
NO CALLS Nothing phoned home. The whole distribution installs with no network calls at install time or first launch, and the add-ons are found locally, then on mounted volumes, before anything is downloaded.
03 Shapes

The same product, from a laptop to an air-gapped rack.

Each deployment shape, how it is installed, and what runs in it
How What you run
Laptop The installer, or pip install "provisa[embedded]" on Python 3.12, and not on Linux aarch64 Everything natively. No Docker.
Linux box AppImage Bundles the core and observability container images and stages compose files out to a writable location — so unlike the row above, this path uses Docker. A non-interactive first launch installs a systemd unit so Provisa starts on boot.
One VM, one team Docker Compose One command brings up the server, the engine and the connectors. The demo upstreams and the telemetry stack are separate compose projects, so they start and stop on their own.
Kubernetes Helm Scales engine workers and validates its own values. Authentication is chosen at install time and does not require Firebase.
Cloud VM Terraform, GCP / AWS / Azure Provisions the stack, stages the release artifacts, runs it under systemd. AWS builds a multi-node cluster behind load balancers, and the interview lets you switch pgwire, Bolt, MCP and gRPC on or off.
Air-gapped Any of the above No network calls at install time or first launch. The Python version is pinned, so a mirror knows which wheels to hold. Local embedding models via Ollama or HuggingFace.

04 Your engine

You already have the engine. Point at it.

# Federate on a Trino coordinator you already run
TRINO_HOST=trino.internal TRINO_PORT=8080 provisa run

If your coordinator is behind a URL rather than a host and port, PROVISA_ENGINE_URL is the documented alternative.

# Or federate in your own PostgreSQL. The extensions it federates
# through have to be installed in that server.
pip install provisa-pg-ext
provisa pg-ext install --docker my-postgres
docker restart my-postgres          # pg_duckdb loads only at server start
provisa pg-ext install --docker my-postgres --create

The pg-ext bundles are built for PostgreSQL 16 only, on linux-x64 and darwin-arm64. A managed service without filesystem access — RDS, Cloud SQL — cannot take them; use the extensions the service offers.

05 Licence

Two different things are called a licence. Here are both.

Provisa is source-available under Business Source License 1.1. Production use is free for an organization that, with its affiliates, has fewer than 100 employees and contractors and under USD 1,000,000 in annual revenue, budget or expenditure, with 90 days' grace if you cross either threshold. Any other production use needs a commercial licence. Each released version becomes GNU General Public License, Version 2.0 or later on the fourth anniversary of that version's first public availability. Non-production use, evaluation included, is free at any size, forever.

Separately, and confusingly similarly named, there is a file. An Unregistered marker appears in the footer from first launch, whenever the deployment is not licensed — it is not an expiry event. Provisa runs for a 30-day trial without a licence; past 30 days an unlicensed deployment also shows a banner in the UI and a notice on each protocol's own channel. Nothing stops working: no feature gate, no row limit, no read-only mode, no expiry.

That notice travels on each protocol's own non-fatal channel — pgwire NoticeResponse, Bolt success metadata, Flight app_metadata, gRPC trailing metadata, a REST header — and it never modifies the result body, the row stream, or any schema-typed field. A licence reminder that cannot corrupt a result set is a design decision, and it cannot even fail the request it rides on.

That file is free. You get it by registering on a web form and clicking the confirmation link; the signed file arrives after that. It proves its own validity offline, with Ed25519, and is tied to the machine it was issued for, so an air-gapped install is licensed like any other. The licence is requested by you, from a browser — not by the install, which makes no network calls at all — and applying it starts no telemetry either.

NOT THE SAME The free licence file is a registration artifact. It is not the BSL production grant. If your organization is over either threshold, you need a commercial licence to run Provisa in production — and the free file does not change that.
